Documento de comprensión del proyecto

1¿Qué resuelve este proyecto?

Cuando un cliente quiere registrar a Periferia como su proveedor, le envía un formulario para llenar y le pide adjuntar soportes. Hoy una persona copia esos datos a mano. Este proyecto es un agente que lo hace solo.

El agente, a partir de una solicitud recibida por correo:

  1. Lee la solicitud y entiende qué campos y soportes pide.
  2. Busca cada dato en el repositorio maestro de Periferia.
  3. Llena el formulario en el mismo formato que mandó el cliente (Excel, PDF o portal).
  4. Arma un paquete para firma: formulario + soportes + checklist + borrador de correo.
  5. Avisa qué falta o qué confirmar, y nunca envía ni firma sin autorización humana.

Tú le hablas por un chat ("procesa el caso X") y él va mostrando cada paso.

2Las tres ideas que explican todo

01

El agente no inventa datos

El modelo no conoce el NIT ni la cuenta. Esos valores solo salen de las herramientas. El agente decide cuándo usarlas; el dato siempre viene de ellas.

02

Tres responsabilidades separadas

Comportamiento en el prompt, conocimiento en knowledge, ejecución en tools. Cambiar una regla no toca el motor.

03

El modelo es intercambiable

Funciona con un modelo falso (mock, sin clave) o uno real (OpenAI, Anthropic). Cambiarlo es cambiar una variable de entorno.

Jerarquía de dependencias (de abajo hacia arriba)

domain/piezas base, no dependen de nada
tools/usan domain para hacer el trabajo real
llm/el "enchufe" del modelo, independiente
agent/usa tools + llm: es el motor del ciclo
server.tsusa agent y sirve el chat web

Las capas de abajo no saben que existen las de arriba. Eso hace el código fácil de probar y de cambiar por partes.

4¿Cómo funciona por dentro?

Supón que escribes: "Procesa el caso ec-corp-andina. No envíes nada."

web/app.js
(navegador) → server.ts
(API /api/chat) → agent/loop.ts
(EL CICLO)
dentro del ciclo, se repite:
1. pregunta
al modelo → 2. el modelo pide
una herramienta → 3. valida (zod)
y ejecuta → 4. devuelve
el resultado ↺
orden de herramientas:
leer→ mapear→ generar→ armar

El ciclo se repite (modelo → herramienta → modelo…) hasta que el modelo tiene todo y responde con texto. Hay un tope de 25 vueltas para que nunca se quede dando vueltas infinitas. Al final devuelve { reply, toolCalls, needsConfirmation } y el chat muestra el resumen, cada herramienta usada y, si aplica, el aviso de confirmación.

5Las 5 herramientas

El agente solo puede hacer lo que estas herramientas permiten. Cada una valida sus argumentos y devuelve siempre { ok, data } o { ok:false, error } — nunca "explota".

HerramientaQué haceResultado
leer_solicitudAbre la solicitud del cliente y su plantillaPaís, cliente, formato, campos y soportes pedidos
mapear_camposCruza cada campo con el maestro usando el glosarioCampos llenos, faltantes y a confirmar
generar_formularioCrea el formulario en el formato pedido.xlsx, .pdf o valores-portal.md
armar_paqueteCopia soportes, arma checklist y borrador de correoCarpeta paquete/ + si está listo para firma
simular_envioSimula el envío (solo con confirmación humana)ENVIO-SIMULADO.md o error

Los tres estados de un campo

LLENOLo encontró con certeza. Se escribe el valor.
FALTANTENo existe en el maestro. No se inventa. Se reporta.
REQUIERE CONFIRMACIÓNLo encontró pero hay una duda (ej. cliente de Ecuador pide "RUC", Periferia solo tiene NIT). Se llena y se marca para que un humano confirme.

Qué bloquea la firma

El paquete queda "listo para firma" solo si todos los soportes exigidos están presentes y vigentes. Lo bloquea un soporte ausente o uno vencido. Un campo faltante no bloquea la firma, pero sí aparece en el checklist.

7Cómo probarlo

Opción rápida: la demo (sin navegador, sin clave)

npm install
npm run demo

Procesa los 4 casos de corrido y muestra un resumen de cada uno. Los resultados quedan en out/.

Opción completa: el chat

npm run dev

Abre http://localhost:3001 y escribe, por ejemplo: "Procesa el caso ec-corp-andina. No envíes nada todavía." Verás el resumen, cada herramienta que usó y un aviso si espera tu confirmación.

8Glosario rápido

AgenteEl programa que conversa, decide qué herramientas usar y responde.
Herramienta (tool)Función concreta que hace una tarea y devuelve datos. Única fuente de valores reales.
Ciclo del agenteEl bucle "pregunto al modelo → ejecuto herramienta → repito".
Adaptador LLMLa pieza que habla con el modelo (mock, OpenAI o Anthropic).
MaestroLa ficha con todos los datos de Periferia.
FixtureDato de entrada de ejemplo que da Periferia.
zodLibrería que valida la forma de los argumentos antes de ejecutar una herramienta.
Confirmación humanaEl agente se detiene y pregunta antes de cualquier acción externa.
